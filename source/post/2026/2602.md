## 背景

在很久以前，我给我的Blog的主题加了 [Hugo][hugo] 的针对 [Mermaid][mermaid] 和 [Chart.js][chartjs] shortcodes 的支持。但是之支持迁入代码的方式。
如果文档很复杂，在Markdown里写大段的代码体验观感也不是很好。
而现在很多Markdown生态里是支持通过代码块的方式嵌入的。
同时现在很多插件可以直接按文件后缀编辑文件，然后直接指向文件的形式引用进来，这样可维护性会好很多。

我之前也懒得一个一个组件去研究和何种模式的测试搭配，现在AI很强了，刚好可以让它帮我把这个优化干了。
并且可以让这些插件都支持各种引入方式，确实是省事儿不少。

实测下来写代码还是Claude强，Google Gemini 3 Pro/Flash 也好，GPT 5.2/5.1-Codex-Max也好都会不同层度的瞎写。
Google Gemini 3 Pro写代码感觉比GPT 5.2强一点。但是通用总结，比如让它给我改Markdown的lingt错误Google Gemini 3 Pro比GPT 5.2差很多。

以下就是花了差不多2个小时，使用的Claude Opus 4.5模型，一口气消耗了Github copilot 75个高级Request（Copilot Pro+订阅的5%）。
最后完成了对 [Mermaid][mermaid]、[Chart.js][chartjs]、[Excalidraw][excalidraw]、[draw.io/diagrams.net][diagramsnet] 的统一支持各种引用模式的支持。

## AI自动生成的测试用例

This page demonstrates all supported methods for rendering diagrams and charts:

- **[Draw.io/diagrams.net][diagramsnet]** - `.drawio` files
- **[Mermaid][mermaid]** - `.mermaid` files
- **[Excalidraw][excalidraw]** - `.excalidraw` files  
- **[Chart.js][chartjs]** - `.chart.json` files
- **[ECharts][echarts]** - `.echarts.json` files
- **[Plotly.js][plotly]** - `.plotly.json` files
- **[D2][d2]** - `.d2` files, rendered to inline SVG at build time
- **[PlantUML][plantuml]** - `.puml` / `.plantuml` files, rendered to inline SVG at build time

Each format supports 4 usage methods:

1. Image syntax: `![](file.ext)`
2. Code block: ` ```language `
3. Shortcode with src: `{{</* type src="file" */>}}`
4. Shortcode inline: `{{</* type */>}}content{{</* /type */>}}`

## 6. [Plotly.js][plotly] 测试

[Plotly.js][plotly] 的 partial bundle（basic / gl3d / cartesian 等）互相覆盖全局 `Plotly`，无法叠加。因此加载策略是：默认只加载最小包（`plotly-basic`，含 scatter/bar/pie）；当页面里同时出现最小特性图表和声明了扩展的图表（如 3D 的 `extensions="gl3d"`）时，自动升级到完整包。本页同时有 2D 和 3D，所以会用完整包渲染。

### 6.1 图片语法引用 .plotly.json（2D 数学函数）

![Plotly 二维函数图](2602-test-plotly-sin.plotly.json)

### 6.2 代码块方式（2D 数学函数）

## 7. [D2][d2] 测试

D2 使用构建时渲染。2026-10-07 核对官方 `@d2lang/d2@0.1.34` 发布包时，浏览器入口 `dist/browser/index.js` 的未压缩大小是 11,514,165 字节（约 11.5 MB），本地以 gzip 默认级别压缩后为 8,559,566 字节（约 8.56 MB），具体数值随压缩实现略有差异；这是该入口文件的测量值，实际传输量还受 CDN 编码和缓存影响。D2.js 能在浏览器中通过 Web Worker 和 WASM 编译、渲染图表，适合需要在线编辑的页面。本站主要展示文章里的静态图，采用 CLI 输出 SVG，可以省去读者端的编译器下载和运行。[D2.js 接入文档](https://github.com/d2lang/d2/tree/master/d2js/js)、[发布包文件列表](https://data.jsdelivr.com/v1/package/npm/@d2lang/d2@0.1.34/flat) 和 [SVG 导出文档](https://d2lang.com/tour/exports/) 分别说明这几项依据。

四种入口都由 Hugo 模板收集内容，构建脚本调用 D2 CLI 后，Hugo 将 SVG 内联进页面。这样保留了 SVG 中的链接和 tooltip；如果使用普通 `<img>` 引用 SVG，链接不会生效，具体差异见 [D2 导出 FAQ](https://d2lang.com/tour/faq/#no-interactivity-in-svg-export)。同一文件的不同引用使用不同的 SVG ID，避免本页重复引用时相互干扰。窄屏下保留 SVG 的原始尺寸并允许横向滚动，避免把文字缩到难以阅读。

本地需要 Python 3.9+、Hugo 和 D2 CLI；本节使用 D2 v0.9.0。按 [D2 安装文档](https://d2lang.com/tour/install/) 安装后，构建命令如下。`--buildDrafts` 等 Hugo 构建参数原样传给正式构建；CI 和 `deploy.sh` 也调用同一脚本。

```bash
python scripts/build-d2.py --buildDrafts --renderToMemory
```

若工具不在 PATH 中，可设置 `HUGO_BINARY` 和 `D2_BINARY` 为可执行文件路径。脚本每次重新渲染引用的图表，包含相对导入的 `.d2` 文件和本地图片变更；生成文件位于已忽略的 `assets/d2-generated/`。修改 D2 内容或依赖后，应重新执行该脚本，再用 `hugo server` 预览，脚本自身不提供 watch 模式。直接执行 Hugo 时，缺少所需 SVG 会报错，不会退回显示源码或占位图。

`src` 只接受相对文章目录的本地路径；外部文件中的相对导入和图片以该文件所在目录为基准，内联图以文章目录为基准。布局、主题和留白等参数写在 D2 的 `vars.d2-config` 中。当前接入只导出根画板；多画板切换动画和 PNG 导出不在本节测试范围内；单画板的虚线流动动画见下方示例。图中使用远程 icon 时，构建仍需访问该地址；本节用例没有远程图像依赖。

### 7.5 虚线流动动画

7.1 和 7.3 复用的 `.d2` 文件已给连线添加以下属性。动画由 SVG 自带的 CSS 执行，不需要读者下载 D2 运行时；系统设置“减少动态效果”时，本站会停止这些动画。这里的运动用于示意数据流向，并不代表实际流量。

```text
source -> build -> svg: {
  style.animated: true
  style.stroke-dash: 3
}
```

`animated` 和 `stroke-dash` 是 D2 的原生样式，具体约束见 [D2 连线样式](https://d2lang.com/tour/style/)。

## 图表主题

页面外框使用深蓝灰背景，正文和图表仍在浅色阅读区内。选主题时比较了深色、灰度和浅色方案，最终采用浅色画布，流程图和数值图以蓝青色为主，PlantUML 使用深色线条；数值图保留多个可辨认的系列颜色，文章显式指定的颜色仍然优先。运行时默认值集中在主题的 `partials/diagram-theme.html`，没有额外加载主题包。

| 工具 | 采用的主题或默认值 | 取舍与覆盖方式 |
| --- | --- | --- |
| Mermaid | `base` + 蓝青色 `themeVariables` | 相比打印取向的 `neutral` 增加浅色分组；可通过图内配置覆盖。[主题文档](https://mermaid.js.org/config/theming.html) |

| PlantUML | `plain` | 白底、深色文字与线条、无阴影；优先保证时序图标签的对比度。图内 `!theme` 可覆盖。[内置主题](https://plantuml.com/theme) |
| ECharts | 本地蓝青色调色板、浅灰网格 | 使用原生主题对象，不下载额外主题脚本；`option` 中的显式样式优先。[样式机制](https://echarts.apache.org/handbook/en/concepts/style/) |
| Plotly.js | 本地浅色 `layout.template` | 默认设置调色板、字体和坐标网格；图内 `layout` 或 `template` 可覆盖。[模板机制](https://plotly.com/javascript/layout-template/) |
| Chart.js | 系统字体、深灰文字、浅灰网格 | 保留内置 Colors 插件和数据集的显式配色，避免改掉数据的颜色含义。[颜色机制](https://www.chartjs.org/docs/latest/general/colors.html) |
| Excalidraw / Draw.io | 保留文件内的主题和颜色 | 草图、架构图的局部颜色常有含义，网站不对导出的画布做滤镜或强制反色。 |
